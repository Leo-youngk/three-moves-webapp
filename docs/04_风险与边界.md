# 04 风险与边界

## 本轮不做什么
- 不重写页面
- 不改产品定义
- 不扩功能
- 不在这一轮实现中国版通知
- 不引入账号体系
- 不引入云同步
- 不引入新的产品迭代需求

## 主要风险
- 把基础设施问题误当成产品问题，导致重写页面
- 把海外可用的链路直接搬到中国环境，造成不可访问
- 把通知、调度、存储和部署混在一起，后续难以拆分
- 迁移时引入新的 UI 变化，破坏已验证体验

## 边界要求
- 先复制，再抽离
- 先保留产品层，再替换基础设施
- 先做可验证的迁移工作区，再考虑中国落地
- 所有变更都要能回到当前已验证版本

## 迁移态度
这轮的目标是整理边界和依赖，不是借迁移名义做产品升级。

## 冻结基线
- 01 当前版本保留项 是产品基线
- 06 目录地图 是职责边界基线
- 后续所有迁移任务都必须先对齐这两份文档，再进入基础设施替换
