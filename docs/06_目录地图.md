# 06 目录地图

这个迁移工作区的目标，是把“产品层”和“基础设施层”分开管理。下面是当前目录职责。

## 根目录
- `src/`：产品代码、页面、组件、状态、基础数据模型
- `public/`：静态资源、PWA 资源、service worker、图标
- `docs/`：迁移说明、保留项、替换项、阶段计划、风险边界
- `infra/`：基础设施耦合清单、后续替换说明、平台依赖记录
- `deploy/`：部署相关说明、目标平台占位、后续发布准备

## 产品层
### `src/app/`
- 页面路由与布局
- `Today / Reminder / Night / History / Install`
- `layout.tsx`、`loading.tsx`、`error.tsx`、`not-found.tsx`

### `src/components/`
- 页面级组件
- 安装引导
- PWA 注册
- 提醒开关
- 页面壳

### `src/hooks/`
- 本地状态读取与写入
- 日期滚动逻辑

### `src/lib/domain/`
- 日常条目模型
- 日期与状态规则

### `src/lib/storage/`
- 本地持久化实现
- 只属于产品层的数据读写

### `src/lib/constants/`
- 页面路由常量
- 提醒文案和导航常量

## 基础设施层
### `src/lib/reminders/`
- push 订阅
- 服务端发送
- VAPID 配置
- install id
- 这些模块是后续替换最频繁的部分

### `src/app/api/reminders/`
- 订阅保存接口
- 定时发送接口
- 这些接口后续要跟着目标平台重接

### `public/sw.js`
- service worker 入口
- 只负责最小提醒壳

### `public/manifest.webmanifest`
- PWA 安装信息
- 名称、图标、启动壳

### `public/icons/`
- 安装后图标资源

### `vercel.json`
- 当前部署定时任务绑定

## 迁移规则
- 页面和文案先留在 `src/`，不要挪到基础设施目录
- 只有和平台绑定的部分才进 `infra/`
- 只有和发布/部署绑定的部分才进 `deploy/`
- 后续替换基础设施时，优先改 `infra/` 和 `deploy/`，不要直接动产品页面

## 冻结入口
- `docs/01_当前版本保留项.md` 定义共享产品基线
- `docs/02_必须替换的基础设施项.md` 定义后续替换范围
- `docs/07_基线冻结清单.md` 会作为迁移执行时的最小检查单
